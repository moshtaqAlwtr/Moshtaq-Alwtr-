# موقع مشتاق الوتر الشخصي

بورتفوليو شخصي بواجهة React، بوضعين (ليلي وساطع) ولغتين (عربي/إنجليزي) مع دعم كامل لاتجاه RTL و LTR.

**Personal portfolio — React, dual theme (dark/light), bilingual (Arabic/English) with full RTL & LTR support.**

## التقنيات

- **React 18** + **Vite 5**
- **TailwindCSS 3** — نظام تصميم قائم على متغيّرات CSS
- **Framer Motion** — الحركات والانتقالات
- **lucide-react** — الأيقونات

## التشغيل محلياً

```bash
npm install
npm run dev
```

## البناء

```bash
npm run build      # ينتج مجلد dist/
npm run preview    # معاينة نسخة الإنتاج
```

## النشر على GitHub Pages

المشروع مهيّأ للمستودع `Moshtaq-Alwtr-`:
`https://moshtaqalwtr.github.io/Moshtaq-Alwtr-/`

**مهم:** GitHub Pages في هذا المستودع تخدم من جذر الفرع `main` — لا من فرع
`gh-pages`. فالبناء يُرفع إلى `main`، والكود المصدري يعيش على فرع `source`:

```bash
npm run deploy        # يبني ويرفع dist إلى main  ← يحدّث الموقع الحيّ
npm run push:source   # يرفع الكود المصدري إلى فرع source
```

> لو رفعت الكود المصدري إلى `main` بالخطأ، سينكسر الموقع الحيّ — لأن Pages
> ستقدّم `index.html` الذي يشير إلى `/src/main.jsx` غير المبني.

للنشر على نطاق خاص (جذر الدومين):

```bash
DEPLOY_TARGET=root npm run build
```

## نظام التصميم

### الوضع الليلي والساطع

كل الألوان معرّفة كمتغيّرات CSS في [src/index.css](src/index.css) على شكل ثلاثيات `R G B`،
ما يسمح لـ Tailwind بتطبيق الشفافية عليها (`bg-brand/10`). الثيمان يعيدان تعريف
**نفس أسماء المتغيّرات**، فلا يحتاج أي مكوّن أن يعرف أي وضع مفعّل:

```css
:root, [data-theme='dark'] { --bg: 8 8 12;      --brand: 139 124 255; ... }
[data-theme='light']       { --bg: 252 252 253; --brand: 105 84 226;  ... }
```

الهوية: **نحاسي دافئ** على أرضية فحمية دافئة.

| الرمز | ليلي | ساطع | التباين على الخلفية |
|---|---|---|---|
| `--bg` | `#0C0A09` | `#FDFCFB` | — |
| `--surface` | `#1C1917` | `#FFFFFF` | — |
| `--brand` | `#FF8F3F` | `#C2410C` | 8.7:1 / 5.1:1 |
| `--brand-2` | `#FF5D73` | `#B45309` | 6.6:1 / 4.9:1 |
| `--brand-3` | `#FFD166` | `#A16207` | — |

> النسخة الساطعة أغمق عمداً: درجة النحاسي الليلية تعطي 2.3:1 فقط على الأبيض.
> وفي المقابل `--brand-2` يبقى في الجهة الكهرمانية لا الوردية — تغميق الطرفين
> معاً حتى يصلح للأبيض يجعلهما قرمزياً واحداً ويضيع طابع النحاس.

يُحسم الوضع في سكربت صغير داخل `<head>` **قبل أول رسم للصفحة**، فلا يحدث وميض
أبيض عند فتح الموقع في الوضع الليلي. الاختيار يُحفظ في `localStorage`
(`mw-theme`)، وأول زيارة تتبع إعداد النظام.

### الخطوط

| الاستخدام | الخط |
|---|---|
| العربية | **المراعي (Almarai)** |
| اللاتينية والأرقام | **Inter** |
| الكود | **JetBrains Mono** |

stack واحد يخدم اللغتين: `'Inter', 'Almarai'`.

Inter لا يحتوي حروفاً عربية، فالعربي يسقط تلقائياً على المراعي بينما تُرسم
الحروف اللاتينية والأرقام من Inter — حتى الكلمات اللاتينية داخل جملة عربية.
لو جاء المراعي أولاً لاستحوذ على اللاتيني أيضاً لأنه يحمل حروفاً لاتينية.

> المراعي يوفّر الأوزان `300/400/700/800` فقط. مطابقة الخطوط في CSS تحوّل
> الوزن 500 إلى 400 و 600 إلى 700 — أوزان حقيقية لا مُصطنعة — فالفجوات آمنة.
> والعربي يأخذ `line-height: 1.95` لأن المراعي يحمل التشكيل فوق السطر.

## نظام اللغتين

الفصل بين **البنية** و**النص** يمنع اختلاف الملفين مع الوقت:

```
src/data/structure.js   ← المعرّفات، الأيقونات، الألوان، مستويات المهارات، التقنيات
src/i18n/ar.js          ← النص العربي فقط
src/i18n/en.js          ← النص الإنجليزي فقط
```

المكوّنات تقرأ الاثنين معاً عبر `useI18n()`:

```jsx
const { t, lang, toggleLang, isRTL } = useI18n()
<h2>{t.projects.title}</h2>
```

تبديل اللغة يغيّر `lang` و `dir` على `<html>`، ويحدّث `<title>` و `meta description`،
ويُحفظ في `localStorage` (`mw-lang`). الزيارة الأولى تفتح **بالعربية** دائماً
(الجمهور المستهدف عربي حتى لو كان جهازه بلغة إنجليزية)، والإنجليزية بضغطة واحدة.

### إضافة نص جديد

أضِف المفتاح في **كلا** الملفين `ar.js` و `en.js` بنفس المسار، ثم استخدمه عبر `t`.

### إضافة مشروع جديد

1. أضِف البنية في `src/data/structure.js` ضمن `projectsMeta`:

```js
{
  id: 'myProject',        // المفتاح الرابط بين البنية والنص
  icon: 'Receipt',        // اسم أيقونة من src/components/icons.js
  category: 'systems',    // يجب أن يوجد له مفتاح في projects.filters
  featured: true,
  visual: 'dashboard',    // dashboard | factory | map | subscriptions | store | contract
  hue: 258,               // درجة لون البطاقة (0-360)
  stack: ['Laravel', 'React'],
}
```

2. أضِف النص في `ar.js` و `en.js` تحت `projects.items.myProject`
   (`title`, `subtitle`, `summary`, `problem`, `solution`, `features`).

> **ملاحظة:** الأيقونات تُستورد بأسمائها صراحةً في `src/components/icons.js`
> بدل استيراد lucide بالكامل — هذا يقلّص الحزمة من ‎1085KB إلى ‎~350KB.
> عند استخدام أيقونة جديدة أضِفها إلى ذلك الملف أولاً.

### مخططات المشاريع (`ProjectVisual`)

بطاقات المشاريع لا تستخدم صوراً — بل مخططات UI مرسومة بـ CSS و SVG من متغيّرات
الثيم، فتتكيّف مع الوضعين ولا تضيف أي حجم تحميل. المتاح حالياً:
`dashboard`, `factory`, `map`, `subscriptions`, `store`, `contract`.

### إذا ظهر خطأ ``The `bg-bg` class does not exist``

كان يحدث لأن `postcss.config.js` كان يمرّر `tailwindcss: {}` بلا مسار، فيبحث
Tailwind عن `tailwind.config.js` **بالنسبة لمجلّد التشغيل الحالي** لا لمجلّد
المشروع. عند تشغيل الخادم من أي مجلّد آخر، لا يجد الإعدادات ويرجع للثيم
الافتراضي — فتختفي كل الألوان المخصّصة (`bg-bg`، `text-text` ...).

الحل مطبّق الآن: `postcss.config.js` و `tailwind.config.js` يستخدمان مسارات
مطلقة مشتقّة من موقع الملف نفسه، فلا يعتمدان على مجلّد التشغيل إطلاقاً.

**ملاحظة أخرى:** إذا رأيت الخطأ رغم ذلك، تأكّد أنه لا يوجد خادم Vite قديم يعمل
على المنفذ. Vite ينتقل تلقائياً لمنفذ آخر (5174، 5175 ...) إذا كان 5173 مشغولاً،
فقد يكون متصفّحك يفتح خادماً قديماً:

```bash
npx kill-port 5173 5174 5175 5176
```

## ملاحظات RTL

- استُخدمت الخصائص المنطقية (`ms-*`, `-start-*`, `border-e`) بدل `left/right`.
- **مهم:** لا تضع `dir="ltr"` على عنصر يستخدم `-start-*` أو `-end-*` — الخصائص
  المنطقية تُحسب باتجاه العنصر نفسه، فينقلب موضعه. ضع `dir` على عنصر داخلي.
- النصوص اللاتينية داخل فقرة عربية (البريد، الهاتف) مغلّفة بـ `<bdi>` لتُقرأ
  من اليسار لليمين مع بقائها في بداية السطر.

## تحسين محركات البحث (SEO)

### المشكلة التي كانت موجودة

الموقع تطبيق React يُرسم في المتصفح، فالملف الذي يستلمه جوجل أول مرة كان:

```html
<body><div id="root"></div></body>   <!-- صفر كلمات -->
```

جوجل ينفّذ الجافاسكربت، لكنه يضعه في **طابور انتظار منفصل** بأولوية أقل بكثير
من HTML الجاهز. صفحة بلا نص قابل للقراءة = عائق حقيقي في الترتيب.

### الحل: Prerendering

أمر `npm run build` صار ثلاث خطوات:

```
vite build                                  # حزمة المتصفح
vite build --ssr src/entry-server.jsx       # حزمة الخادم
node scripts/prerender.mjs                  # يرسم الصفحة ويحقنها في dist/index.html
```

النتيجة: **٩٣٤ كلمة قابلة للفهرسة** في HTML الأولي بدل صفر، والاسم يظهر ٥ مرات
في المحتوى المرئي.

> السكربت **يُفشل البناء** إذا نزل النص تحت ١٠٠ كلمة — حتى لا يمر رسم فارغ دون
> أن ينتبه أحد.

### ملاحظات تقنية

- `readTheme()` و `readLang()` في [providers.jsx](src/app/providers.jsx) يتحققان من
  `typeof window === 'undefined'`، فالرسم على الخادم يخرج **النسخة العربية الليلية** —
  وهي الافتراضي الصحيح لجمهور الموقع.
- `CountUp` يرسم القيمة النهائية على الخادم؛ لو بدأ من صفر لتجمّدت
  «٠ مشروع منجز» داخل HTML الذي يقرأه جوجل.
- الرسم على الخادم يحمل حالة framer-motion قبل الحركة (٩١ عنصر بـ `opacity:0`).
  جوجل ينفّذ JS فيرى الصفحة كاملة، لكن كتلة `<noscript>` في
  [index.html](index.html) تفكّ الإخفاء عند تعطيل الجافاسكربت.
- جملة قسم «كيف أفكّر» تضع المسافة **داخل** كل كلمة لا في `margin`، وإلا لقرأها
  الزاحف ككلمة واحدة ملتصقة.

### البيانات المنظّمة

`ProfilePage` + `Person` + `WebSite` في [index.html](index.html)، مع
`alternateName` لصيغ الاسم المختلفة (Moshtaq Alwtr / مشتاق قائد الوتر /
Mushtaq Alwatr) لأن الناس تبحث بأكثر من طريقة.

### ما لا يفعله الكود

الترتيب في جوجل لا يُبرمَج. الكود يجعل الموقع **قابلاً للفهرسة**، لكن الظهور يحتاج:

1. **نشر الموقع** — لا شيء يُفهرَس قبل أن يكون على الإنترنت.
2. **Google Search Console** — أضف الموقع واطلب الفهرسة:
   <https://search.google.com/search-console>
3. **روابط من مواقع أخرى** — GitHub، LinkedIn، X، خمسات/مستقل. هذه أقوى إشارة.
4. **وقت** — الفهرسة تأخذ أياماً إلى أسابيع.

استعلام «مشتاق الوتر» اسم شخصي ومنافسته ضعيفة، فالوصول للصدارة واقعي جداً بعد
النشر والفهرسة.

## السيرة الذاتية

الملفات في `public/cv/`:

| اللغة | الملف | الحجم |
|---|---|---|
| العربية | `moshtaq-alwtr-cv-ar.pdf` | 5.7MB · صفحة واحدة |
| الإنجليزية | `moshtaq-alwtr-cv-en.pdf` | 0.4MB · صفحتان |

لتحديث أي نسخة: استبدل الملف بنفس الاسم، وحدّث `sizeMB` و `pages` في
`resumes` داخل [structure.js](src/data/structure.js).

زر التحميل يظهر في مكانين — ضمن أزرار الواجهة، وكأيقونة في شريط التنقّل —
ويعرض قائمة باللغتين مع الحجم، فلا يبدأ أحد تحميل 5.7MB على بيانات الجوال
دون أن يعرف.

> **الحجم**: النسخة العربية 5.7MB لأنها صفحة مصمّمة كصورة عالية الدقة. يُفضّل
> ضغطها عبر <https://www.ilovepdf.com/compress_pdf> ثم استبدال الملف — الفرق
> في سرعة التحميل كبير، خصوصاً على الجوال.

### ملاحظة عند البناء على ويندوز

إذا فشل `npm run build` برسالة `EPERM ... dist\cv\*.pdf`، فهناك برنامج يمسك
الملف (تبويب متصفح يعرض الـ PDF، أو خادم معاينة شغّال). أغلقه ثم أعد البناء.

## حسابات التواصل

معرّفة في `socials` داخل [structure.js](src/data/structure.js)، وتظهر في مكانين:
قسم «تواصل» وتذييل الصفحة — من مكوّن واحد `SocialLinks`.

لإضافة حساب: أضِف سطراً إلى `socials` (المعرّف، الرابط، الأيقونة، لون المنصّة)،
ثم أضِف اسمه في `socials` داخل `ar.js` و `en.js`.

> **مهم لمحركات البحث**: كل رابط هنا مُدرَج أيضاً في `sameAs` داخل
> [index.html](index.html). هذه هي الطريقة التي يربط بها جوجل حساباتك بشخص
> واحد — وهي **أقوى إشارة متاحة** لاستعلام باسمك. عند إضافة حساب جديد، أضِفه
> في الموضعين.

تيك توك و X ليس لهما أيقونة في مكتبة lucide، فرُسمتا يدوياً في
[BrandIcons.jsx](src/components/BrandIcons.jsx).
